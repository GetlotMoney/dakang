### V-02　主题（Topic）命名规则

我方现值：

| 方向 | 主题 | 说明 |
|---|---|---|
| 上行 | `up/{deviceNo}/{type}` | type 共 6 个取值，见下表 |
| 下行 | `down/{deviceNo}/cmd` | **只有这一个下行主题**，具体指令类型放在报文体的 cmdType 字段 |

上行 type 取值集合（**这 6 个是全集，平台只接收这 6 个，其余一律丢弃**）：

| type | 含义 | 详见 |
|---|---|---|
| `heartbeat` | 心跳，在线判定依据 | V-03 |
| `status` | 运行状态与故障上报 | V-03 |
| `telemetry` | 遥测（TDS / 水温 / 滤芯 / 信号） | V-03 |
| `ack` | 指令接受回执 | **V-04** |
| `result` | 指令执行结果（含实际出水量） | **V-04** |
| `replay` | 断网补传，载荷为原 status/ack/result 报文并带原 msgId | **V-05** |

⚠ `ack` 与 `replay` 请勿遗漏：缺 `ack` 会导致每一条出水指令都被判失败（V-04），
缺 `replay` 会导致断网期间的数据永久丢失（V-05）。

请确认贵方设备能否按此订阅/发布；若贵方已有固定主题规则，请给出并说明 type 取值集合。

### V-03　报文格式与字段定义

请提供各类报文的字段定义与样例（JSON 或二进制格式说明）：

| 报文类型 | 需明确 |
|---|---|
| 心跳 | 字段清单；上报频率；平台判定离线的建议阈值 |
| 遥测 | 支持哪些字段（TDS / 水温 / 滤芯寿命 / 信号强度）；各字段单位与精度；不支持的字段如何表达 |
| 状态变更 | 状态取值集合（在线/离线/运行中/故障/维护…）；是否主动上报 |
| **时间格式** | 我方现值：报文内时间一律 `yyyyMMddHHmmss` 东八区字符串。贵方若用 Unix 时间戳或 UTC，请注明——此项对不上会导致全部上行报文解析失败 |
| **协议版本** | 报文是否带版本号字段？设备分批次生产、固件迭代后新旧协议如何共存？ |

> 我方当前实现的遥测字段为 TDS、原水 TDS、水温、信号强度、滤芯寿命，若贵方设备不支持其中某项，请注明——页面当前会直接展示这些数值。

### V-04　出水指令与执行回执

这是取水链路的核心，需完整定义：

| 环节 | 需明确 |
|---|---|
| 指令下发 | 报文字段；水量、水种、出水口编号的表达方式 |
| ACK（接受回执） | **`ackCode` 必填**：只有 `ackCode` = `accepted`（不分大小写）才算受理；**留空、缺字段或任何其他值（含 `busy`）一律判为拒绝并将指令置失败**。⚠ 请贵方固件务必显式回 `accepted`，「不回 ackCode」的实现会导致每一条出水指令都被判失败。若贵方有「忙碌可重试」语义，请明确取值，我方将增加重试分支 |
| result（执行结果） | 实际出水量字段名、单位、精度；成功与失败的表达 |
| 部分完成 | 下单 10L 实出 4.98L 这类情况如何表达 |
| 超时 | 设备无响应时平台应等待多久；是否支持指令查询 |
| 并发出水 | 一台设备的多个出水口能否同时出水？「忙」是设备级还是出水口级？（决定我方扫码预检按设备拦还是按出水口拦） |

## 六、P1 设备控制与实体卡

### V-12　远程控制指令集

我方已定义的指令类型（cmdType，放在 `down/{deviceNo}/cmd` 报文体内）：

| cmdType | 指令 | 我方用途 |
|---:|---|---|
| 1 | 开始出水 | 用户下单后下发，见 V-04 |
| 2 | 停止出水 | 立即中止进行中的出水（即"紧急停止"，报文须锚定服务端确认的活动出水订单） |
| 3 | 查询状态 | 运维主动拉取设备状态 |
| 4 | 锁机 | 停用设备，拒绝所有出水 |
| 5 | 解锁 | 恢复设备可用 |
| 6 | 参数同步 | 下发配置参数 |
| 7 | 重启 | 远程重启设备 |
| 8 | 价格同步 | 平台改价后推送到设备 |

> **2026-08-04 勘误（重要，若贵方已按旧版实现请务必重做映射）**：本表此前的版本在
> 位置 2 漏列"停止出水"，导致 cmdType 2～7 整体错位一格。上表为更正后的**权威**映射，
> 与我方平台实际下发完全一致。按旧表实现的后果：我方发"停止出水(2)"贵方执行查询状态
> （**紧急停止失效**）、我方发"参数同步(6)"贵方执行重启。

请确认贵方设备实际支持哪些（不支持的直接标注），并给出各自的报文字段与贵方的类型编号。

补充确认：
- V-12.1　价格同步：设备本地是否存储价格？平台改价后的同步机制？
- V-12.2　紧急停止：停止后如何恢复？是否需要现场操作？
- V-12.3　参数同步(cmdType=6)的**参数键集**：请给出贵方设备支持配置的每一个参数，
  逐项说明「键名、数据类型、单位、取值范围、默认值、是否需要重启生效、是否可回读」。
  **两点与贵方固件设计直接相关**：①在收到贵方清单前，平台不预过滤参数键——
  **请固件对不认识的键做防御性忽略并在 result 中回报**，不要假设平台已经过滤；
  ②我方 payload 为扁平 JSON 对象（键名 `^[A-Za-z][A-Za-z0-9_]{0,31}$`、值仅
  字符串/数字/布尔、无嵌套无 null、键数 ≤32、字符串值 ≤64 字符），
  若贵方参数形态与此冲突请指出。

- V-12.4　**result 报文的 `partial` 字段**：我方以 `partial=true` 表示「部分生效」
  （指令落「部分完成」而非「成功」，且不回写参数快照）。请确认三点：该字段是否存在？
  是否为 JSON boolean（还是字符串 `"true"`/数字 `1`）？部分完成时是否同时给出
  「哪些子项成功」？贵方确认类型后我方将收紧解析（非约定类型即拒绝该 result 并留痕）。
