# 六维达康需求基线

本目录将 2026-07-05 的 Excel 需求池快照纳入仓库，作为需求分析、接口契约、实现和验收的统一入口。

## 文件说明

- `source/敏捷项目管理-六维达康需求池完善副本-2026-07-05.xlsx`：原始工作簿，只作为不可变证据保留。
- `requirements-pool.csv`：从“①需求池（关联项目）”导出的 110 条需求、38 个原始业务字段，并保留 Excel 源表行号。
- `version-plan.csv`：从“②版本开发计划”导出的 22 条有效版本任务，排除了两个 `VER-EMPTY-*` 模板行。
- `demo-business-chain-matrix.md`：产品业务需求能力链、宏观端到端业务旅程及其状态的唯一来源。
- `decisions.md`：用户确认、范围收缩和需求覆盖变化的决策日志。

## 权威性顺序

需求发生冲突时，按以下顺序判断：

1. 资金与设备安全铁律；
2. 用户最新明确确认的范围和业务口径；
3. `AGENTS.md`、主工作流和已验收的页面/接口契约（二期商城契约：`docs/contracts/E2E-09-mall-contract.md`）；
4. 本目录的 Excel 需求池快照；
5. 由 Excel 派生的 CSV 和业务链矩阵。

原始 Excel 是“需求池与版本计划快照”，不是自动授权实施全部需求的最终签字 PRD。工作簿中的 `AI执行判断=可直接执行` 只表示资料整理时的建议，不能绕过当前工作流的验收门。用户最新确认或 `decisions.md` 中较新的决策覆盖旧口径。

## 导入范围

已纳入：“①需求池（关联项目）”110 条有效需求、“②版本开发计划”22 条有效版本任务、“发布版本”（确认 V1.0/V2.0/V3.0 时间边界）、“项目汇总”（仅核验六维达康项目关联需求）。

未作为项目事实导入：“💡 模板使用说明”（通用敏捷模板）、“③版本 Bug 记录”（通用示例 Bug，不是达康项目真实缺陷）、“项目汇总”第 2～8 行（模板项目示例）、`VER-EMPTY-1/2`（工作簿已标注应归档或删除的空白模板记录）。

## 数据质量结论

1. 需求表实际有 **110 条、110 个唯一需求 ID**，核心字段无空值；工作簿文字口径（73+36）少算 1 条，基线以实际 110 行为准。MVP/骨架分解与 B 链归并的唯一口径见 `demo-business-chain-matrix.md` §1。
2. 版本计划中的进度全部停留在“未开始”，只能作为 2026-07-05 的排期快照；当前实际状态以 `docs/demo-module-status.md` 与 `demo-business-chain-matrix.md` 为准。
3. Excel 中 `AI输出位置` 仍使用 `water-station/...` 旧规划路径；本项目实际根目录为 `dakang/`，不得照抄生成重复工程。

## 使用与更新约束

- 实施状态唯一来源：模块×端状态见 `docs/demo-module-status.md`；B01～B24 与宏观 `E2E-*` 状态见 `demo-business-chain-matrix.md`，改动后必须运行 `python3 tools/check-demo-baseline.py`。
- 工作流、必读顺序与验收门以 `AGENTS.md` 和 `docs/development-workflow.md` 为准，本目录不另设流程。
- 禁止直接改写 `source/` 中原始 Excel。后续收到新版需求池时，应并列保存新快照、重新导出，并在决策日志中说明差异。
