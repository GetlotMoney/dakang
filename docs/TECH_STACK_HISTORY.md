# 技术与视觉演进记录

## 版本类型说明

- `SYS-*`：系统和底层功能版本。
- `UI-*`：页面、视觉和交互版本。
- `UI-PREVIEW-*`：只用于用户选择方向的视觉预览，不代表正式小程序已经改版。
- `UI-FIGMA-*`：进入 Figma 的可编辑视觉选型稿，不代表正式小程序已经改版。
- `SKILL-*`：Agent / Skill 工作流版本。
- `DATA-*`：数据与数据库版本。
- `DOC-*`：文档和交付文件版本。

不同前缀互不比较大小。例如 `UI-PREVIEW-GREEN-V1A` 只表示第一组健康绿预览 A，不表示系统功能升级。

## SYS-MINIAPP-BOOT-V1：小程序冷启动会话兼容

- 日期与状态：2026-08-10，已完成。
- 本次改的是哪个对象：小程序 `App.vue` 冷启动时的会话恢复；不改登录接口、令牌规则、角色权限或任何业务页面。
- 目标问题：未登录用户冷启动时，既有会话恢复会按预期拒绝，但旧代码没有等待并处理该结果，微信开发者工具会记录未处理的“会话未建立”异常。
- 采用技术：把 `onLaunch` 改为异步回调，等待 `restoreSession()`，并只在启动边界把没有会话视为正常未登录状态；C01 后续仍走正式登录流程。
- 替换了什么：把 `void accountStore.restoreSession()` 替换为带 `try/catch` 的 `await accountStore.restoreSession()`，并新增冷启动回归测试。
- 实际可见效果：没有历史会话时应用仍稳定进入 C01，不再产生未处理的异步异常；登录失败或后端不可达仍由页面按真实结果提示。
- 选择原因：异常在应用启动边界处理最清楚，不需要放宽请求层规则，也不会形成测试账号直通或万能密码。
- 已知限制：本修正不会启动本地后端，也不会让未登录用户进入受保护页面；真实登录、会话续期和角色权限仍依赖对应接口。
- 素材位置：`miniapp/src/App.vue` 与 `miniapp/src/App.test.ts`。
- 验证命令与结果：冷启动回归测试通过；`pnpm type-check`、`pnpm lint` 和全量 `pnpm test` 均通过；微信模拟器控制台未再出现未处理会话异常。
- 回退方式：恢复 `App.vue` 原来的非等待调用并移除冷启动测试即可；该回退会重新暴露微信冷启动未处理异常。
